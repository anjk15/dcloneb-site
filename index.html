Get started

About 5 minutes, on macOS or Windows. You need Claude: the desktop app or Claude Code. Open a terminal (macOS: Terminal; Windows: PowerShell) and follow the steps.

  1. Get uv

    uv is a free installer for Python tools. Skip this if you already have it.

    macOS:

    curl -LsSf https://astral.sh/uv/install.sh | sh

    Windows (PowerShell):

    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

    Then close the terminal and open a new one.

  2. Install dcloneb

    uv tool install "dcloneb[mcp] @ https://anjk15.github.io/dcloneb-site/downloads/dcloneb-0.5.0-py3-none-any.whl"

    Using Databricks? Install this one instead:

    uv tool install "dcloneb[mcp,databricks] @ https://anjk15.github.io/dcloneb-site/downloads/dcloneb-0.5.0-py3-none-any.whl"

  3. Check the version

    dcloneb --version

    It should print dcloneb 0.5.0.

  4. Connect Claude

    Pick the Claude you use. This creates your workspace folder, ~/dcloneb-workspace.

    Claude Desktop app

    Best for most people. You approve with a click in your browser, and Claude can't skip it.

    Quit Claude Desktop first (Cmd+Q on macOS, or File, Exit on Windows), then run:

    dcloneb mcp install --workspace ~/dcloneb-workspace
dcloneb mcp test

    Open Claude Desktop again.

    Claude Code (terminal or VS Code)

    For developers. Everything happens in your terminal or editor.

    dcloneb mcp install --client claude-code --workspace ~/dcloneb-workspace
dcloneb mcp test --client claude-code

    Start a new Claude Code session.

    Approval is a guardrail here: Claude Code can also run shell commands, so watch what it proposes.

  5. Ask for data

    Put your schema.sql in ~/dcloneb-workspace, start a new chat, and ask: Use the dcloneb tools to make 20 rows per table from schema.sql in my dcloneb workspace. Approve the summary, and your CSVs appear in ~/dcloneb-workspace/<name>/csv/.

Already installed?

To get version 0.5.0, run step 2 again, then step 3 to check. Restart Claude afterwards. Your workspace and settings stay as they are.

If something goes wrong

  • command not found: run uv tool update-shell, then open a new terminal.
  • Claude doesn't see dcloneb: quit Claude completely, run dcloneb mcp test, and open Claude again.
  • Still stuck? Run dcloneb mcp test and share what it prints.

Use with Databricks

Make test data shaped like your real tables, without copying a single real row. You talk to Claude; dcloneb does the work.

Just type connect and answer a few short questions. Most answers are just a number.

  1. Sign in

    Set up as in Get started, using the Databricks install in step 2. Then sign in once with the Databricks CLI. dcloneb never sees your password or token.

    uv tool install "dcloneb[mcp,databricks] @ https://anjk15.github.io/dcloneb-site/downloads/dcloneb-0.5.0-py3-none-any.whl"
databricks auth login --profile dev

  2. Type connect

    You: connect

    Claude: Which catalog? 1. main 2. samples

    Then the schema and the tables. Where there is only one choice (one warehouse, say), it is picked for you.

  3. dcloneb looks at your data

    It reads a sample of the tables you picked, using fixed read-only queries. Before it reads any actual values it asks:

    Claude: May dcloneb read the values of accounts.status? You: yes

  4. Review the rules

    You get one numbered list: 2. balance is 0 to 25,000, 4. when status is CLOSED, balance is 0 (all 90 closed accounts had 0). These are suggestions until you keep them.

    You: delete 3, make 2 0 to 10,000

  5. Describe the data

    Claude: Describe the data you want: how many rows, and any specific records or edge cases.

    You: 20 customers with one account each, plus one closed account with balance 500 to test quarantine.

  6. Approve and get your files

    Check the plain-English summary, click Approve, and the CSVs appear in your workspace folder. The report says every rule held, apart from the one negative test you asked for.

  7. Change anything

    Claude: Anything to change, add, or remove? You: make it 50, and add a customer with no accounts.

    You approve Changes since generated: customers 21 → 52. The new files go to generated-2, and the first folder stays as it was.

  8. Push to Databricks

    You: push it to Databricks. Claude: Where? 1. it_test (new schema, recommended) 2. sandbox

    Optional. You approve once, and dcloneb creates the tables, loads them, and checks every row count and link.

What you get

  • One CSV per table, with every reference pointing at a real row.
  • A report: every rule holds, except the bad rows you asked for.
  • A folder that gives the exact same files when you run it again.

Safe by design

  • Reading uses only fixed, read-only queries.
  • It writes to Databricks only after you approve a push, and only into a new schema or one you pick. It never replaces tables and never touches your source schema.
  • It reads a sample, so its figures are estimates.
  • Your data is generated on your computer.

Good to know

Your data and privacy

Data is generated on your computer and files stay on your computer, inside your workspace folder; dcloneb will never overwrite a file. Nothing is generated until you click Approve on a page served only on 127.0.0.1 (it works once and expires in 10 minutes). Claude sees your schema, rules, and summaries, so those reach your model provider; generated values are shared only if you ask Claude to preview rows.

What's supported

Column types

SMALLINT INT BIGINT TINYINT SMALLSERIAL SERIAL BIGSERIAL DECIMAL FLOAT DOUBLE BOOLEAN VARCHAR TEXT CHAR DATE TIMESTAMP TIMESTAMPNTZ TIMESTAMPTZ UUID

Business rules

RuleMeaning
rangethe value is >= / > min and <= / < max (whichever bounds are given), compared exactly; timestamps in UTC
allowed_valuesthe value is one of `values` (decimals by value, text exact and case-sensitive)
formatthe value matches the format; only `email` (the documented strict ASCII syntax)
id_formatversion 2: the value is `prefix` followed by exactly `digits` characters from `characters` (digits by default, or upper, upper_digits), like ACC-00042
value_kinda generation guide for what the values are (product names, cities, ...); checked as non-empty text that fits
conditionalwhen `when.column` equals `when.equals`, `then.column` must equal `then.equals` (same table, equality only)
null_ratea generation setting: the share of rows left NULL (not a constraint)

Not supported yet (refused with a clear reason)

  • FKs sharing child columns with another FK (`overlapping_foreign_keys`)
  • CHECK (`check_constraint`)
  • generated columns (`generated_column`)
  • partial or expression unique indexes, table properties (`unsupported_plan_diagnostic`)
  • triggers, functions, views, row-level security (the CSVs satisfy declared constraints only)

Limits

Up to 100,000 rows per table and 1,000,000 in total by default.

Databricks: the fine print

dcloneb reads table metadata, then runs aggregate queries over a sample (100,000 rows by default). A query that runs too long is cancelled on the warehouse. It reads category values (like status names) only for columns you approve. Sign-in stays with the Databricks CLI: no token reaches Claude, logs, or files.

Databricks permissions (the fewest needed)
ToGrant
Read your tablesUSE CATALOG on the catalog; USE SCHEMA and SELECT on the schema; CAN USE on the SQL warehouse
Push into a new schemaUSE CATALOG and CREATE SCHEMA on the target catalog
Push into an existing schemaUSE SCHEMA, CREATE TABLE and CREATE VOLUME on that schema (plus USE CATALOG)

dcloneb owns what it creates, so it needs no MODIFY and nothing on your source beyond reading. If a permission is missing, Claude shows the exact GRANT statements for an admin. Best: push with a separate Databricks CLI profile, such as a service principal, that has only these grants.

Scenarios and bad rows (negative tests)

Scenarios let you ask for exact rows. The rows you name keep their values and links, and every other row follows all the rules. A row breaks a rule only if you ask for it as a negative test, and the report lists it. The report also says the pipeline outcome is not verified by dcloneb: you load the files and check your pipeline yourself.

Use it without Claude 
dcloneb make schema.sql --rules rules.json --rows 100
